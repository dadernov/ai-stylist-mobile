# Развёртывание AI-сервера на новом сервере

Гардероб хранится в приложении, но сервер **не stateless**: `accounts.sqlite3`
содержит аккаунты и сессии, `quota.sqlite3` содержит расход и журнал примерок с
временными результатами. При переносе обязательны согласованные резервные копии
обеих SQLite-баз (SQLite backup API либо копирование после остановки сервиса).
Храни копии с правами 0600, не добавляй их в git. Сначала восстанови базы и проверь
вход на новом сервере, только потом отключай старый.

## Обновление после аудита 23.09.2026

- Нужны новые модули `jobs.py` и `request_guard.py` вместе с `app.py`, `access.py`
  и обновлённым `requirements.txt`. Установщик копирует их автоматически.
- Запускается **один uvicorn worker**. При старте сервер помечает прерванные
  задания ошибкой, возвращает не начатые шаги и не повторяет сомнительные платные
  операции автоматически. Для нескольких workers нужна отдельная очередь с lease.
- `AI_DEVICE_DAILY_QUOTA` ограничивает аккаунт, `AI_GLOBAL_DAILY_QUOTA` весь сервис,
  `AI_MAX_ACTIVE_TRYONS` число активных примерок. Стоимость резервируется до старта.
  Уже отправленный провайдеру шаг учитывается и при отказе проверки результата.
- Клиент отправляет `request_id` и `async_mode=true`, получает 202, затем читает
  `GET /tryon-jobs/{request_id}` с `Authorization` и `X-Session-Token`. Повтор
  того же ID идемпотентен; кнопка перегенерации создаёт новый ID и seed.
- nginx должен пропускать `/tryon-jobs/` и иметь отдельный лимит опроса. Одного
  обновления Python недостаточно. `/docs` и старые маршруты остаются закрыты снаружи.
- В `AI_ALLOWED_ORIGINS` укажи точный HTTPS-origin веб-приложения, без завершающего
  слеша. CORS разрешает GET/POST/OPTIONS и заголовок сессии; wildcard не нужен.
- Крупные результаты очищаются по возрасту и общему бюджету при завершении заданий.
  Записи идентификаторов сохраняются, чтобы старый повтор не запустил платную работу.
  Это не облачная синхронизация гардероба; важные изображения сохраняются клиентом.
- Перед обновлением: `npm test`, `npm run typecheck`, Python `unittest discover`,
  экспорт web/iOS через Expo. Браузерные регрессии: `tests/audit-ui.cjs` (моки API).

Следующие разделы описывают установку. Исторические заметки июля в конце документа
относятся к старому серверу, а не к текущей схеме хранения.

## Что нужно

- VPS с Ubuntu 22.04 или 24.04, **2 vCPU / 4 ГБ RAM / 15 ГБ диска**. Без torch
  venv стал заметно легче: остаются onnxruntime + Pillow, а из моделей — u2net
  для rembg (~176 МБ) и распознавание одежды (~94 МБ в рантайме, плюс ~111 МБ
  текстовой башни, которая нужна только установщику).
  GPU не нужен: тяжёлая генерация уходит во внешний FASHN API.
- `FASHN_API_KEY` — ключ платного API (без него `/tryon-generate*` не работают,
  `/analyze` и `/tryon-avatar` работают).
- Доступ наружу к `api.fashn.ai` и `cdn.fashn.ai`, к HuggingFace и GitHub (для установки).

## Установка (10–15 минут)

```bash
git clone git@github.com:dadernov/ai-stylist-mobile.git /root/ai-stylist
cd /root/ai-stylist/ai-server
sudo bash deploy/install.sh
```

Скрипт: ставит python3-venv, кладёт код в `/opt/wardrobe/ai-server`, создаёт venv,
ставит зависимости, **заранее скачивает модели** (u2net для rembg и fashion SigLIP
для распознавания) и пересобирает под них текстовые признаки, ставит и запускает
systemd-юнит `wardrobe-ai`, ждёт 200 на `/docs`.

Переменные: `APP_DIR`, `PORT`, `SERVICE_NAME`, `ENV_FILE`, `INSTALL_SYSTEMD=0`.

Шаг с `download_analysis_model.py` обязателен и при обновлении: `text_features.npy`
помечен отпечатком набора промптов, и с чужим отпечатком сервер откажется
стартовать, вместо того чтобы молча отвечать мимо.

Сервис работает под системным пользователем `wardrobe`, а не от root; каталог
приложения отдаётся ему установщиком. Кеши моделей лежат внутри каталога
приложения, потому что домашней папки у этого пользователя нет.

Перед первым запуском обязательно задать `AI_CLIENT_TOKENS` в env-файле — без
него примерка и анализ отвечают 503. Тот же токен должен попасть в сборку
приложения как `EXPO_PUBLIC_AI_CLIENT_TOKEN`.

Дальше вписать ключ и перезапустить:

```bash
sudo nano /etc/wardrobe-ai.env    # FASHN_API_KEY=...
sudo systemctl restart wardrobe-ai
```

Все переменные окружения с их прод-значениями — в `deploy/env.example`
(смысл каждой FASHN_* — в `README.md`).

## HTTPS

Клиент ходит по HTTPS, поэтому нужен nginx + сертификат. Своего домена у проекта нет —
на проде использовался `<IP>.nip.io`:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo sed "s/__HOST__/<НОВЫЙ_IP>.nip.io/" deploy/nginx-wardrobe-ai.conf \
  | sudo tee /etc/nginx/sites-available/wardrobe-ai
sudo ln -sf /etc/nginx/sites-available/wardrobe-ai /etc/nginx/sites-enabled/
sudo certbot --nginx -d <НОВЫЙ_IP>.nip.io     # сам дописывает 443 и редирект с 80
sudo nginx -t && sudo systemctl reload nginx
```

`client_max_body_size 30m` и таймауты 300 c в конфиге обязательны: фото большие,
генерация лука идёт до 240 c.

## Переключить приложение

Базовый URL задан в `src/constants/ai.ts` (`FALLBACK_AI_BASE_URL`) и перебивается
`EXPO_PUBLIC_AI_BASE_URL`. Поменять на `https://<НОВЫЙ_IP>.nip.io`, пересобрать клиент.

## Проверка после переезда

Наружу nginx пускает `/auth/`, `/analyze`, `/tryon-generate-look` и `/tryon-jobs/`
(с отдельными лимитами запросов по IP).
Остальные эндпоинты и `/docs` проверяются на самом сервере напрямую в uvicorn:

```bash
curl -sf http://127.0.0.1:8000/docs -o /dev/null && echo docs ok
curl -s -o /dev/null -w '%{http_code}\n' https://<НОВЫЙ_IP>.nip.io/auth/me       # без токенов: 401
curl -s -o /dev/null -w '%{http_code}\n' https://<НОВЫЙ_IP>.nip.io/tryon-jobs/test # без токенов: 401
curl -s -o /dev/null -w '%{http_code}\n' https://<НОВЫЙ_IP>.nip.io/docs          # снаружи должно быть 404
```

Для анализа и платной генерации требуются токен приложения и сессия аккаунта.
Не вставляй реальные токены в историю shell и не используй платную генерацию
в качестве health-check. Проверка CORS выполняется безопасным OPTIONS-запросом.

## Проверено 28.07.2026

Скрипт прогнан на чистом окружении (изолированный каталог + свой venv + свои кеши
моделей, порт 8010, systemd-юнит `wardrobe-ai-test`) на Ubuntu 24.04 с python 3.12.
Результат: venv 1.6 ГБ, модели скачались (u2net 176 МБ, CLIP), сервис поднялся,
`/analyze`, `/tryon-avatar`, `/tryon-model` вернули 200 за ~1–3 c на 2 vCPU.
Ключ FASHN живой, `api.fashn.ai/v1/credits` → 200, на балансе 160 кредитов.
Тестовый стенд после проверки удалён, прод не трогали.

По ходу проверки нашлось и починено: в `requirements.txt` был `rembg` без `[cpu]`,
из-за чего не ставился `onnxruntime` и `remove()` падал на первом же запросе —
установка «по README» на чистой машине не взлетала.

Отдельная грабля старого сервера: в `/etc/environment` прописан мёртвый
`http(s)_proxy` (194.87.40.45:6614) — из-за него `pip` на этой машине не работает
без `env -u http_proxy -u https_proxy`. На новом сервере просто не прописывай прокси.

## Прод разошёлся с git (на 28.07.2026)

На сервере крутился `app.py` от 02.06.2026 21:48, а `main` ушёл вперёд (коммит от
03.06). Это разные ветки одной работы: на проде face lock через cv2 Haar-каскады,
в `main` — pose-based face lock и быстрый режим примерки. Прод-версия сохранена
в ветке `server-snapshot-2026-07-28`, чтобы не пропала вместе с сервером.
**Деплой идёт с `main`** — если после переезда примерка «потеряет лицо» хуже, чем
раньше, сравни с этой веткой: `git diff main server-snapshot-2026-07-28 -- ai-server/app.py`.

## Чего на старом сервере НЕТ (чтобы не искать при переезде)

- Никакой базы, загруженных файлов, состояния: кеш примерок — в памяти процесса,
  теряется при рестарте, это норма.
- `mediapipe` не установлен — определение позы работает через bbox-fallback.
  Ставится опционально: `pip install -r requirements-ml.txt`.
- Прокси `http(s)_proxy` в юните был прописан, но мёртв; во FASHN приложение ходит
  напрямую. На новом сервере прокси не нужен.
- Старый сервер (Aeza) был общий: на нём же крутились `x-ui` и `light-pay` — к этому
  проекту они отношения не имеют, переносить не надо.
