# AI Server (MVP)

MVP AI: background removal + dominant color + palette + базовая классификация вещи + адаптивная статичная примерка по фото + аватарный режим примерки.

## Run locally

```bash
cd ai-server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python download_analysis_model.py
uvicorn app:app --host 0.0.0.0 --port 8000
```

Опционально для детекции позы (распознавание одежды её не требует):

```bash
pip install -r requirements-ml.txt
```

## Доступ

Вход и регистрация требуют только токена сборки:

```
POST /auth/register  {login, password, displayName}
POST /auth/login     {login, password}
POST /auth/logout
GET  /auth/me
Authorization: Bearer <один из AI_CLIENT_TOKENS>
```

Всё остальное требует ещё и живой сессии:

```
X-Session-Token: <токен из /auth/login>
```

Пароли хешируются scrypt из стандартной библиотеки; в базе лежит не сам токен
сессии, а его отпечаток. После пяти неверных попыток подряд аккаунт на минуту
закрывается, чтобы перебор был бессмысленно медленным. Сессия живёт год и
переживает перезапуск приложения — входить заново при каждом открытии не нужно.

Суточная квота считается по аккаунту, а не по устройству: переустановка
приложения больше не обнуляет израсходованное.

Пустой `AI_CLIENT_TOKENS` не открывает сервер, а закрывает: примерка ответит
503. Это сделано намеренно — платный эндпоинт не должен открываться из-за
забытой переменной окружения.

Токен живёт в сборке приложения, поэтому его можно оттуда извлечь. Считать его
секретом нельзя; он нужен, чтобы поднять порог и чтобы утёкший ключ можно было
отозвать здесь, не выпуская новую версию сервера. Ущерб от утёкшего токена
ограничивает `AI_DEVICE_DAILY_QUOTA` — суточное число проходов генерации на
одну установку. Учёт ведётся в SQLite и переживает перезапуск.

## Endpoint

`POST /analyze` (multipart form: `file`, optional `section_hint`: `Верх`, `Низ`, `Обувь`, `Сумки`, `Верхняя одежда`).

Recognition runs locally on Marqo's fashion SigLIP (quantized ONNX, Apache-2.0),
without torch or an external image API. On a benchmark of 42 labelled garment
photos it names the right category in 93% of cases and has the right one in its
top three every time; the general-purpose CLIP it replaced scored 76% and 93%.

Weights are pinned by `download_analysis_model.py`; set `AI_ANALYSIS_MODEL_DIR`
to override the default `models/clip` directory. Missing weights return a
partial result with `analysisSource: "unavailable"`, never a made-up category.

The installer computes `text_features.npy` once with the quantized text model;
only the vision model and that small table are loaded at runtime. The file is
fingerprinted with the prompt set it was built from, so a stale one makes the
server refuse to start rather than answer from mismatched prompts — re-run the
downloader after changing the category or prompt dictionary.
For photographs of people, the dominant colour is left unset: the foreground
mask can include skin and other garments, not just the target item.

Responses include `categoryCandidates`, `needsReview`, `warnings`,
`backgroundRemoved` and `analysisSource`. Category, pattern and dominant colour
may be null. Candidate scores are relative similarities, not calibrated
probabilities. Season is a category-based suggestion, not fabric analysis.
The client preserves the original photo and lets users confirm or correct
results. Upload limit: 15 MB / 25 megapixels; a busy analyser returns 503.

Tests: `python -m unittest test_analysis.py` from this directory.

Response:
```json
{
  "dominantColor": "#aabbcc",
  "palette": ["#...", "#..."],
  "bgRemovedBase64": "data:image/png;base64,...",
  "category": "Футболка",
  "season": "Демисезон",
  "pattern": "Однотонный"
}
```

### Quality-only примерка

`POST /tryon-generate-look`: multipart `person_file`, любой из `top_file`, `bottom_file`, `shoes_file`, `outer_file`; категории `top_category` / `outer_category` и `tuck_mode`.
Одна вещь не требует полного комплекта. Параметры `quality_mode=fast` и `compare_mode` принимаются для старых клиентов, но не меняют политику: всегда `tryon-max`, `generation_mode=quality`, без дополнительных повторных проходов.

```bash
export FASHN_API_KEY=...
export FASHN_QUALITY_RESOLUTION=2k
export FASHN_QUALITY_MAX_WAIT_SECONDS=240
export FASHN_IMAGE_MAX_SIDE=2048
python download_face_model.py
python download_parsing_model.py
```

Комплект из двух-четырёх вещей применяется одним вызовом `tryon-max`, как и отдельная вещь. Исходные фото размещаются на общем референсе 2048x2048 с сохранением пропорций, принтов и полных подолов, без обрезки. Промпт связывает каждую вещь с её расположением. Верхняя одежда остаётся наружным слоем. Лимит резервирует одну операцию; скрытых платных повторов нет. Качество остаётся `quality / 2k`, отдельного быстрого режима в интерфейсе нет. Генеративная модель не гарантирует физически точную посадку.

Если вместе с верхней одеждой выбран внутренний верх, промпт явно требует полностью расстёгнутую верхнюю одежду и видимый принт внутреннего слоя. Для отдельного плаща сохраняется состояние застёжек на референсе. Это инструкция генератору, а не автоматическая проверка того, что все застёжки действительно открыты.

Защита лица обязательна. Локальный YuNet находит единственное видимое лицо до платного запроса. После генерации сравниваются пять ориентиров лица, а не размер его рамки. Совмещение кадра опирается на детали фона вне силуэта человека: SIFT, взаимные соответствия и ограниченное similarity-преобразование RANSAC с проверкой пространственного распределения опорных точек. Лицо проверяет совместимость с этим преобразованием, но не задаёт второй масштаб всему телу. При недостатке фоновых деталей допускается только небольшой перенос по согласованным ориентирам лица; их погрешность не масштабирует и не поворачивает тело. Незначительные отклонения не вызывают лишнего преобразования. Исходное фото никогда не трансформируется. Если лицо на полном кадре пропущено детектором, проверяется увеличенная область головы. Существенное смещение человека, несогласованные ориентиры и ненадёжный силуэт отклоняются. В журнал попадает только причина отказа, без фотографий и координат лица. Модель YuNet распространяется под MIT: [OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet). Загрузчик проверяет SHA-256.

Разница пропорций исходника и результата сама по себе не означает искажение. Если генератор добавил поля, результат вписывается в исходный кадр равномерным масштабированием и центральной обрезкой, без растягивания человека. После этого остаётся обязательная проверка ориентиров лица: обрезанный или существенно увеличенный человек не принимается автоматически.

Итог собирается в полном разрешении исходника с учётом EXIF-ориентации (в пределах лимита загрузки 25 Мп). Детекторы и генератор работают с уменьшенной копией; для финального смешивания увеличиваются только маска и сгенерированный слой, а защищённые пиксели берутся из полноразмерного оригинала. Голова и дальний фон сохраняются из оригинала; тело ниже головы берётся целиком из одного сгенерированного кадра. Маска головы следует контурам волос, лица и шеи, а не заканчивается горизонтальной границей рамки детектора. Сохраняется также весь верх кадра выше линии над глазами. Новый воротник может закрыть шею ниже подбородка; старый воротник не возвращается на вновь открытую кожу.

Перед обработкой встроенные ICC-профили преобразуются в sRGB через LittleCMS, а не просто удаляются. Вход генератора и итоговый PNG явно содержат профиль sRGB. Фото без профиля считаются sRGB; повреждённый профиль отклоняется. Точность сохранения пикселей относится к оригиналу после цветового преобразования и EXIF-ориентации. PNG исключает повторное JPEG-сжатие защищённых областей. Область новой одежды может закрывать часть исходного фона; точность её границы зависит от сегментации. Отказ выделения силуэта и отказ совмещения имеют разные сообщения; в журнале сохраняются код причины и размеры кадров, но не фотографии, URL результатов или координаты лица.

Локальный [SegFormer B0 для одежды](https://huggingface.co/mattmdjaga/segformer_b0_clothes) размечает исходник и совмещённый результат. Эта же разметка используется для силуэтов, кожи, одежды и обуви без U2Net. Используются [ONNX-веса Xenova](https://huggingface.co/Xenova/segformer_b0_clothes), 15 МБ, с закреплённой ревизией и SHA-256; путь задаётся через `AI_PARSING_MODEL`. Недоступность модели останавливает примерку до платного вызова.

`tryon_matte.py` объединяет исходный и новый силуэты основного человека в непрерывную область редактирования. Построчная оболочка включает обе позиции сместившейся кисти или стопы, а также пространство между штанинами: это область одного согласованного кадра, а не утверждение, что каждый её пиксель является телом. Исходная кожа не вклеивается ни поверх, ни рядом с новой одеждой. Отдельные руки, ноги и обувь не восстанавливаются из другого положения тела. Переход к оригиналу находится снаружи обоих силуэтов, на фоне, а не на запястье или подоле. Семантические метки головы ограничены областью обнаруженного лица и шеи.

После совмещения отдельно проверяется покрытие сгенерированного слоя. Если координаты выборки выходят за его кадр внутри области тела, результат отклоняется: недостающие пиксели нельзя заменять исходными конечностями. Исходник допустим только в защищённой голове, дальнем фоне и внешнем переходе маски. Пиксели на последнем ряду кадра остаются допустимыми, если совмещение действительно не выводит их за границы; искусственное сужение покрытия не обрезает обувь.

GrabCut-разрезание тела, локальное растягивание рукавов/низа штанин и TELEA-inpaint не используются. Они и покомпонентное восстановление исходной кожи давали разорванные и дублированные конечности при небольшом изменении позы. Сохранение невыбранной одежды, формы кистей и обуви задаётся генератору инструкцией; попиксельного сохранения всего тела этот подход не обещает. Для босых ног есть отдельное указание не надевать обувь с пола; для брюк требуется посадка каждой штанины по исходной ноге без открытого дубликата рядом.

Проверки включают локальный повтор обработки ранее сохранённого исходника и сырого результата без нового платного вызова, а также регрессии совмещения и покрытия. Генеративная модель всё ещё может ошибиться в анатомии или посадке; сохранение цельного слоя предотвращает добавление второй геометрии постобработкой, но не исправляет произвольный дефект самого генератора. Фон непосредственно возле тела может реконструироваться вместе с ним. Тесты не являются гарантией идеального результата на каждом фото.

Для диагностики с согласия конкретного пользователя доступен выключенный по умолчанию `tryon_debug.py`. Три настройки `AI_TRYON_DEBUG_DIR`, `AI_TRYON_DEBUG_OWNER_SHA256`, `AI_TRYON_DEBUG_UNTIL` разрешают единственное локальное сохранение исходника и ответа генератора до композитинга. Окно и хранение ограничены 30 минутами, доступ к файлам 0600/каталогу 0700; токены и имя владельца не записываются. Платных вызовов диагностический код не запускает. При включении необходим независимый системный таймер удаления каталога и временной конфигурации: таймер Python не гарантирует удаление при остановленном сервере.

Цветовой сдвиг генератора оценивается по устойчивым пикселям неизменного фона; коррекция применяется только к сгенерированному слою. Новая открытая область шеи согласуется с исходным тоном лица. Цвета новой одежды не используются как эталон для коррекции. Ответ генератора запрашивается в PNG. Ответ и журнал содержат времена подготовки, единственного прохода и композита (`timings`, `steps[].durationSeconds`); шаг комплекта называется `outfit`. На согласованном контрольном комплекте из трёх вещей один вызов занял 49 секунд против 185 секунд у прежних трёх вызовов. Это измерение одного случая, а не гарантия задержки или качества для каждого комплекта.

Кеш и объединение одинаковых активных запросов экономят повторные вызовы. Кеш ограничен 64 МБ (`FASHN_LOOK_CACHE_MAX_BYTES`), так как PNG крупнее JPEG. Смена версии маски инвалидирует старые результаты для новых запросов; старые записи истории не перезаписываются. Сервер ждёт единственный проход до `FASHN_QUALITY_MAX_WAIT_SECONDS`, не снижая качество при долгом ответе.

Успешный ответ содержит `status=succeeded`, `outputUrl=data:image/png;base64,...`, `qualityModeUsed=quality`, `modelUsed=tryon-max`. Непроверенный результат не используется как запасной вариант.
